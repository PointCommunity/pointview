Source application integration

How a private product links users into PointView without asking them to choose GitHub metadata.

1. Register the source

An Owner creates a disabled, versioned registration with the immutable slug, display name, exact GitHub owner/repository, private Project node ID and number, GitHub App installation ID, governed area labels, HTTPS origins, return URL prefixes, and Ed25519 public keys. PointView validates repository access, Project identity/schema, and required labels before enablement.

2. Sign on the source backend

Use packages/launch-sdk on the trusted server. Never put a private signing key in browser JavaScript. Each assertion is audience-bound, expires within five minutes, and carries a cryptographically random unique nonce.

jtiUnique, unpredictable, single-use nonce
ContextEnvironment, location, screen name, app version, source revision, and allowlisted return URL

3. POST the assertion

Render a form with method POST, action https://pointview.eaglepass.io/launch (or the Canary URL during integration testing), and exactly one field named launch_token. A user gesture may submit it. Do not place assertions in URLs, analytics, logs, referrers, or persistent browser storage.

4. Preserve user context

  • Label the link “Send feedback” and explain that the current screen context is included.
  • PointView renders verified source, environment, route, screen, version, and revision as read-only.
  • The user enters feedback and optional screenshots only.
  • After submission or cancellation, PointView returns only to an allowlisted source URL.

5. Rotate safely

Add a new public key and deploy the matching source private key before retiring the old key. Keep the overlap longer than the maximum assertion lifetime. Registration changes create a new version; queued records remain bound to the version captured at intake.

Fail closed

Unknown keys, forged or replayed nonces, expired tokens, wrong audience, disabled sources, mismatched origin, unsafe return URLs, and changed source mappings are errors. Do not fall back to URL parameters or user-selected repository fields.

Integration owners must keep private signing keys and GitHub configuration outside source-controlled client code.
