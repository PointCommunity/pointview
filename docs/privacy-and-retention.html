Privacy and retention

What PointView collects, who can see it, what reaches GitHub, and what the retention job removes.

Collected data

  • Feedback text entered intentionally by the user.
  • Up to five screenshots explicitly selected by the user. Accepted PNG, JPEG, and WebP files are decoded, normalized, stripped of metadata, and stored privately.
  • Verified source context: application, environment, route, screen, app version, source revision, and safe return URL.
  • Minimal account identity needed for authorization and ownership.
  • Derived evidence references, decisions, GitHub operation/readback proofs, usage counters, and sanitized audit events.

PointView does not silently capture screens and does not accept video, audio, archives, executables, or arbitrary documents.

Access

RolePermitted access
UserSubmit, list, view, download, and withdraw only their own eligible feedback
AdminReview operations, annotate, and requeue; manage non-Owner account state
OwnerAll Admin functions plus source registrations, settings, secrets references, retention, triage pause, and Owner membership

Cloudflare Access authenticates; the application database authorizes. Direct-origin forwarded headers are not trusted.

What reaches GitHub

Only privacy-minimized, evidence-linked summaries required for an Issue or comment. Raw screenshots, Access assertions, credentials, raw model output, unnecessary email/IP/User-Agent data, and unredacted sensitive content must never be sent to GitHub or logs.

Retention clock

Raw feedback text and screenshot bytes remain for 180 days after every derived unit reaches a terminal disposition. The audited retention job then deletes raw payloads and verifies attachment absence. It retains minimized evidence, decisions, operation/readback proofs, tombstones, and the audit chain for traceability.

Re-running retention is idempotent. A deletion failure is recorded and retried; it must not be represented as successful.

Withdrawal

A submitter may withdraw only their own queued, unleased record. Successful withdrawal removes raw payload and attachment bytes immediately while leaving a content-free tombstone and audit event. Once leasing begins, withdrawal fails with a conflict so a concurrent decision cannot use partially deleted evidence.

Privacy incident response

  1. Pause triage if exposure could continue.
  2. Do not copy raw content into tickets or chat. Record only opaque identifiers and sanitized symptoms.
  3. Determine whether data reached logs, GitHub, backups, or only the private database/volume.
  4. Use the audited application workflow for deletion where possible. Destructive database or backup action requires explicit authorization.
  5. Verify absence, preserve a minimized incident record, correct the root cause, and test the prevention.

Default raw-content retention: 180 days after terminal triage. Owner changes are versioned and audited.
