# Release PointView Production

Read `AGENTS.md`, `.agents/pointview-pipeline-policy.html`, the PointView and homelab repositories' live instructions, the approval, merged PR, and exact candidate evidence. Run only from `pointview-close-issue` after `Approved to merge and deploy production` for the current candidate.

1. Proceed immediately after exact approval. Confirm the merged `main` tree equals the approved PR head tree and both GitHub `Quality / verify` and `Container / amd64` succeed for the merge result. Reuse the exact Canary Zot digest; never rebuild or replace it.
2. Confirm current Production image/configuration and live PVC/PV identities and reclaim policies. Require a fresh, non-empty, restorable database backup or snapshot; rehearse or otherwise verify its restore procedure in a disposable target. Confirm migration compatibility and record the precise non-destructive GitOps rollback commit. Data or destructive schema restoration is not pre-authorized.
3. In an isolated homelab worktree from current Gitea `origin/master`, update `apps/pointview/Chart.yaml` and its lock/vendor artifacts only when needed to adopt the exact app-template generation verified in Canary, then pin migrate, web, triage CronJob, and retention CronJob in `apps/pointview/values.yaml` to the approved Canary tag/digest. Preserve Production URL, release identity, Cloudflare audience, secrets, database, namespace, TLS, labels, resources, StatefulSet, and persistence identities.
4. Run Helm dependency update, lint/render, semantic comparison with the approved Canary generation, targeted pre-commit, `git diff --check`, `node .agents/skills/pointview-release-canary/scripts/check-chart-version.mjs production <homelab-repo>`, and `node .agents/skills/pointview-release-canary/scripts/check-candidate.mjs production <approved-source-sha> <digest> <homelab-repo>`.
5. Commit only intended Production GitOps files, push Gitea `master`, refresh/wait for Argo CD `pointview`, and run `node .agents/skills/pointview-release-canary/scripts/verify-live.mjs production <approved-source-sha> <digest> <homelab-sha>`.
6. Inspect migration, web, triage/retention Job, attachment-storage, and PostgreSQL logs; internal health/readiness; events; restart counts; exact digest; PVC identity; Argo CD sync/health; and every homelab all-green layer. Do not require an authenticated browser or landing-page login check in Production; healthy exact containers plus these runtime and cluster gates are sufficient because application behavior was verified locally before release.
7. Only after Production and the whole cluster are verified green, resolve every PointView digest referenced by active homelab GitOps state, including Canary and Production. Purge obsolete unreferenced PointView image manifests from Zot, then confirm the retained Production digest is still pullable. Never delete a referenced digest, and do not declare the release complete if cleanup fails or the retained digest is unavailable. Zot may reclaim orphaned blobs through its normal delayed background garbage collection; do not wait for that pass or repeat the Production and whole-cluster green checks solely because manifest cleanup occurred.
8. On deployment failure, revert the Production GitOps commit to the recorded previous state and verify recovery. If recovery requires data restoration or destructive schema work, stop and request PM authorization with exact evidence. Do not run image cleanup before a failed deployment has recovered.
9. Report approved Canary identity, merge commit/tree, Production GitOps commit, app-template generation, exact digest, backup/restore evidence, purged manifests, retained references, pre-cleanup all-green evidence, and any rollback action.
