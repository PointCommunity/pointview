Exact GitHub Issue body

<h2>Summary</h2>
<p>Build PointView as a private, separately hosted feedback application for Point Community products. An approved user follows a source-app Feedback link, sees cryptographically verified app/page context, enters feedback, optionally uploads screenshots, and never has to choose a repository, Project, label, or Issue.</p>
<p>Once daily, PointView drains every eligible untriaged record oldest-first and strictly one record at a time. It researches current work, code, documentation, pull requests, and appropriate primary external sources; splits mixed feedback into independently traceable units; and assigns each unit exactly one outcome: merge into one eligible non-Done Issue, create one new Backlog Issue, or consider with no GitHub mutation.</p>

<h2>User evidence</h2>
<ul>
  <li>Users should provide only feedback and optional screenshots; source application/context must be attached automatically.</li>
  <li>Similar feedback should enrich existing work where justified, while mixed submissions may split across multiple outcomes.</li>
  <li>The daily job must continue one item at a time until the eligible queue is empty.</li>
  <li>PointView performs triage only. A human senior developer acting as Project Manager explicitly triggers implementation through each target app's own pipeline.</li>
  <li>Raw feedback/screenshots are retained for 180 days after terminal triage; minimized evidence, decisions, GitHub proofs, and audit lineage remain indefinitely.</li>
</ul>

<h2>Research</h2>
<ul>
  <li>Adopt PointGuide's current repository skills, private Project fields, one-active-development-Issue invariant, full quality gates, immutable Zot image, Argo-managed Canary, exact Production approval phrase, and same-digest promotion.</li>
  <li>Use signed single-use EdDSA launch assertions submitted by form POST; do not trust query parameters or referrers for routing.</li>
  <li>Use defense-in-depth screenshot validation and private normalized storage; raw images never enter GitHub.</li>
  <li>Use a Kubernetes CronJob only as the daily trigger. PostgreSQL singleton and lease invariants provide correctness because scheduled Jobs must be idempotent.</li>
  <li>Use deterministic evidence collection and GitHub application around a strict-schema model decision. The model has hosted web search but no database, GitHub, filesystem, provider-management, or cluster credentials/tools.</li>
  <li>Use a repository-scoped private GitHub App, stable operation markers, pre-write state refresh, and post-write readback.</li>
</ul>

<h2>Scope</h2>
<ul>
  <li>Private Next.js/TypeScript application with PostgreSQL, Cloudflare Access identity, local User/Admin/Owner authorization, and append-only sanitized audit events.</li>
  <li>Source-app registry and launch SDK; verified environment/route/screen/version/revision context; safe return path.</li>
  <li>Text feedback plus up to five normalized PNG/JPEG/WebP screenshots of at most 10 MiB each, stored privately.</li>
  <li>Daily oldest-first singleton triage, lease recovery, per-record retry isolation, deterministic research manifests, strict decision validation, risk-based second review, and usage/cost telemetry.</li>
  <li>Idempotent MERGED, CREATED, and CONSIDERED outcomes with full GitHub/Project readback and no development-status mutation.</li>
  <li>Role-based operations pages, pause/requeue controls, Needs Attention handling, health/readiness/metrics, and audited retention deletion.</li>
  <li>PointGuide-derived repository governance, CI, private PointView Project, and separate homelab Canary/Production applications.</li>
</ul>

<h2>Acceptance criteria</h2>
<ol>
  <li>Every accepted submission has verified source identity/context and requires no user-selected GitHub metadata.</li>
  <li>Forged, expired, replayed, disabled, cross-origin, or misrouted launch assertions fail closed.</li>
  <li>Unsafe uploads, cross-user record access, role escalation, prompt injection, unsupported citations, and out-of-scope model mutations fail closed.</li>
  <li>One daily batch leases at most one record concurrently, processes oldest-first, continues past isolated terminal record failures when safe, and drains until empty unless an Owner pauses it or a blocking integration failure prevents safe progress.</li>
  <li>Every processed unit has evidence-linked lineage and exactly one terminal MERGED, CREATED, or CONSIDERED disposition.</li>
  <li>All non-Done Project Issues are screened; Done work is history only; no mutation targets an Issue that is Done at pre-write refresh.</li>
  <li>Retries and lost responses produce no duplicate Issue or comment; every applied mutation has exact readback proof.</li>
  <li>Created Issues are open, unassigned, in Backlog, HTML-formatted, and carry one type, one or more areas, Priority, Impact, and Effort.</li>
  <li>Automated triage never changes development Status, assigns implementation, creates/changes a branch or PR, starts review/release, merges code, deploys, closes an Issue, or sets Done.</li>
  <li>Raw content is erased 180 days after terminal triage and on valid queued withdrawal; minimized durable provenance remains.</li>
  <li>Core logic maintains at least 80% line coverage and all required source, security, upload, migration, accessibility, responsive-browser, build, and AMD64 container gates pass.</li>
  <li>Canary and Production are isolated; the exact approved Canary image digest is promoted to Production without rebuilding.</li>
</ol>

<h2>Verification</h2>
<ul>
  <li>Unit/property tests for state machines, authorization, JWS/nonces, image validation, redaction, evidence and decision schemas, retry classification, and idempotency.</li>
  <li>PostgreSQL integration tests for first-Owner race, final-Owner protection, singleton batch/lease behavior, crash recovery, attachment compensation, and retention.</li>
  <li>Contract/fault tests for complete Project pagination, GitHub App permissions, Project mutations, status drift, rate limits, and lost responses.</li>
  <li>Adversarial tests for injection in feedback/Issues/code/web, forged routing, cross-user IDs, upload attacks, unsafe citations, and forbidden development actions.</li>
  <li>Playwright/axe validation at 320, 768, and 1280 CSS pixels, 200% zoom, keyboard/touch, reduced motion, and user/admin flows.</li>
  <li>Exact-source/tree/image/digest/GitOps proof, Canary live API/UI/Job verification, whole-cluster health, rollback evidence, and same-digest Production readback.</li>
</ul>

<h2>Out of scope</h2>
<ul>
  <li>Automatically implementing, branching, reviewing, merging, releasing, deploying, closing, or setting Done on feedback-derived Issues.</li>
  <li>Public/anonymous intake, silent screenshots, video/audio/document uploads, and PointGuide knowledge/training functionality.</li>
  <li>Changing other application repositories to add their Feedback link/signing endpoint; PointView supplies the launch SDK/contract, while each real integration is a separate human-triggered Issue in that app's pipeline.</li>
  <li>Automatically reopening or mutating Done Issues.</li>
</ul>
